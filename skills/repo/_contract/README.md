# Repo contract — shared scaffold / standards source of truth

`skills/repo/_contract/` is **not** a skill. It holds the machine contract, scoring scripts, templates, and gold fixture used by `repo-scaffold`, `repo-standards`, and `multi-agent-repo`.

## Change workflow

1. Edit `standards-contract.json` and/or `templates/`
2. Update `fixtures/scaffold-gold/` to match
3. Run `make test-repo-contract`
4. Grep `repo-scaffold` and `repo-standards` SKILL.md for stale paths
5. Bump `version` in `standards-contract.json`

**Rule:** If a path or check is not in `standards-contract.json`, it does not belong in either skill's prose.

## Commands

```bash
# Offline fixture test (skips every GitHub API probe: S4-02, S4-04–S4-14)
CONTRACT_OFFLINE=1 bash scripts/assert-contract.sh fixtures/scaffold-gold app-gold

# Full gap report
bash scripts/score-contract-gaps.sh /path/to/repo app-gold

# Scaffold exit gate (online — includes branch governance when gh is available)
bash scripts/assert-contract.sh "$REPO_ROOT" app-gold
```

## Sources of truth

| File | Owns |
|------|------|
| `core/capabilities/platforms.json` | The platform set and every capability status. Nothing else may restate one. |
| `feature-equivalence.json` | The repo-contract delta only — which artifact makes a capability reachable. |
| `docs/engineering/build-and-release/platform-targets.json` | Versions and provenance, plus a **derived** capability mirror regenerated by `check-platform-targets.sh --sync-capabilities`. |
| `standards-contract.json` | Paths, badges, docs tree, CI, exit gates. |
| `config/github/repository-policy.json` | Branch rulesets, required status-check contexts, enforcement, and the Actions concurrency classification. Read by `standards-inventory.sh` and by `scripts/github-policy.sh`. **Nothing else may restate one of its values** — not a ruleset name, not a required context, not an approving-review count. |

`scripts/check-feature-equivalence.sh` fails loudly whenever these disagree, in either
direction. Adding a platform is therefore a registry edit followed by `--sync-capabilities`
and an artifact entry in `feature-equivalence.json` — never a hand edit in three places.

## Duplicated files are generated, never hand-maintained

Several files must exist in three places: the plugin's own `scripts/`, the scaffold
template `repo-scaffold` renders, and each gold fixture that has to exercise the same
logic a scaffolded repo will run. Hand-maintaining those copies does not work — two forks
were found here, both invisible because nothing compared them:

- `fixtures/*/scripts/check-feature-equivalence.sh` sat on a pre-fix revision of the live
  script for as long as fixtures were outside the lint scope, so the fixtures were testing
  logic the live script no longer had.
- `templates/check-manifest-version-alignment.sh.tmpl` never received
  `--allow-pending-release`, directional ahead/behind drift detection, or the BSD-sed
  `usage()` fix, so every scaffolded repo inherited three already-fixed defects.

The map lives in [`script-sync.json`](script-sync.json) — adding a copy is a data edit.

```bash
bash scripts/sync-contract-scripts.sh            # regenerate every copy from canonical
bash scripts/sync-contract-scripts.sh --check    # assert; exit 1 on drift
```

`assert-contract.sh` runs `--check` first, so the contract cannot be asserted with a forked
copy of itself and `make test-repo-contract` fails on drift.

Two chains matter:

- `core/capabilities/{schema,platforms}.json` → `templates/core/capabilities/*.tmpl`
  (reverse substitution lifts owner/name into `{{...}}`) → the three fixture registries.
  Correcting the live registry therefore reaches the scaffold template automatically.
- each fixture registry → that fixture's `platform-targets.json` capability mirror,
  regenerated by `check-platform-targets.sh --sync-capabilities`.

**Never hand-edit a generated copy.** Edit the canonical source and re-run the sync.

## Profiles

| Profile | Use |
|---------|-----|
| `app-gold` | Greenfield app repos from `repo-scaffold`; polish target for `repo-standards` (default) |
| `plugin-gold` | Agent-kit distribution repos from `repo-scaffold --type plugin`; auto-detected when `canonical/rules/` exists. Generates one adapter per target (Claude, Codex, Cursor, Gemini CLI, OpenCode) from `canonical/`. |

Detect profile: `bash scripts/detect-contract-profile.sh <repo-root>`

Exit gate: P1 = P2 = P3 = 0 on merged standards + multi-agent + plugin (if plugin-gold) deterministic checks.
