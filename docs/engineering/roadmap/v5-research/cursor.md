## KQ2: Which Cursor hook events exist now; what can each read/modify/block; anything new since 3.11?

### Takeaway
21 events, unchanged in count since the repo's Sep 23 measurement; the only additions since are payload fields. Blocking is possible on `preToolUse`, `subagentStart`, `beforeShellExecution`, `beforeMCPExecution`, `beforeReadFile`, `beforeTabFileRead`, and (via `continue:false`) `beforeSubmitPrompt`; `stop`/`subagentStop` can inject a follow-up; everything else is observational.

### Cited Findings
- Event names, exactly: Agent hooks `sessionStart`, `sessionEnd`, `preToolUse`, `postToolUse`, `postToolUseFailure`, `subagentStart`, `subagentStop`, `beforeShellExecution`, `afterShellExecution`, `beforeMCPExecution`, `afterMCPExecution`, `beforeReadFile`, `afterFileEdit`, `beforeSubmitPrompt`, `preCompact`, `stop`, `afterAgentResponse`, `afterAgentThought`; Tab hooks `beforeTabFileRead`, `afterTabFileEdit`; app lifecycle `workspaceOpen` — [Source](https://cursor.com/docs/agent/hooks); same list in the plugin reference — [Source](https://cursor.com/docs/reference/plugins)
- File format: `"version": 1` (positive integer, required) plus `"hooks"` mapping event → array of definitions. Locations by priority: Enterprise MDM (`/Library/Application Support/Cursor/hooks.json`, `/etc/cursor/hooks.json`, `C:\ProgramData\Cursor\hooks.json`) > Team (dashboard) > project `<project-root>/.cursor/hooks.json` > user `~/.cursor/hooks.json`; files are watched and reloaded on save — [Source](https://cursor.com/docs/agent/hooks)
- Per-script options: `command` (required), `type` `"command"|"prompt"` (prompt hooks use an LLM, return `{ ok, reason? }`, accept `model`, replace `$ARGUMENTS`; "Prompt hooks are not supported in cloud agents"), `timeout` (seconds), `loop_limit` (default `5`, `null` removes cap; Claude Code hooks default `null`), `failClosed` (default `false`), `matcher` (regex; `""` or `"*"` matches all) — [Source](https://cursor.com/docs/agent/hooks)
- Exit codes: 0 = use stdout JSON; 2 = block (= `permission: "deny"`, "matches Claude Code behavior"); other = fail open unless `failClosed`. Permission hooks (`beforeShellExecution`, `beforeMCPExecution`, `beforeReadFile`, `beforeTabFileRead`, `subagentStart`, `preToolUse`) "block on invalid JSON or a schema mismatch, even when `failClosed` is false". Merge: `deny` > `ask` > `allow`; `user_message`/`agent_message` concatenated; other fields last-wins — [Source](https://cursor.com/docs/agent/hooks)
- Common input: `conversation_id`, `generation_id`, `model`, `model_id`, `model_params`, `hook_event_name`, `cursor_version`, `workspace_roots`, `user_email`, `transcript_path` — [Source](https://cursor.com/docs/agent/hooks)
- `preToolUse`: in `tool_name`, `tool_input`, `tool_use_id`, `cwd`, `agent_message`; out `permission` (allow/deny; "`ask` accepted but not enforced"), `user_message`, `agent_message`, `updated_input`; blocks — [Source](https://cursor.com/docs/agent/hooks)
- `postToolUse`: in adds `tool_output` (JSON string), `duration` ms; out `updated_mcp_tool_output` (MCP only), `additional_context` (snake_case, not `additionalContext`) — [Source](https://cursor.com/docs/agent/hooks)
- `postToolUseFailure`: `error_message`, `failure_type` (`error`/`timeout`/`permission_denied`), `is_interrupt`; out `additional_context` — [Source](https://cursor.com/docs/agent/hooks)
- `subagentStart`: `subagent_id`, `subagent_type`, `task`, `parent_conversation_id`, `tool_call_id`, `subagent_model`, `is_parallel_worker`, `git_branch`; out `permission` ("`ask` treated as deny"), `user_message`; blocks — [Source](https://cursor.com/docs/agent/hooks)
- `subagentStop`: `status` (`completed`/`error`/`aborted`), `task`, `description`, `summary`, `duration_ms`, `message_count`, `tool_call_count`, `loop_count`, `modified_files`, `agent_transcript_path`; out `followup_message` ("consumed only when `completed`") — [Source](https://cursor.com/docs/agent/hooks)
- `beforeShellExecution`: `command`, `cwd`, `sandbox`; out `permission` allow/deny/ask, `user_message`, `agent_message`; blocks. `afterShellExecution`: `command`, `output`, `duration`, `sandbox`; no output — [Source](https://cursor.com/docs/agent/hooks)
- `beforeMCPExecution`: `tool_name`, `tool_input` (JSON string), `mcp_server_name`, plus `url`/`mcp_server_url` (HTTP/SSE) or `command` (stdio); blocks. `afterMCPExecution`: adds `result_json`, `duration` — [Source](https://cursor.com/docs/agent/hooks)
- `beforeReadFile`: `file_path`, `content`, `attachments` (`type` `file`/`rule`); out `permission` allow/deny, `user_message`; blocks. `afterFileEdit`: `file_path`, `edits` (`old_string`,`new_string`); no output — [Source](https://cursor.com/docs/agent/hooks)
- `beforeSubmitPrompt`: `prompt`, `attachments`; out `continue` (boolean), `user_message`; blocks submission. `afterAgentResponse`: `text`. `afterAgentThought`: `text`, `duration_ms` — [Source](https://cursor.com/docs/agent/hooks)
- `stop`: `status` (`completed`/`aborted`/`error`), `loop_count`; out `followup_message` ("auto-submitted as next user message") — [Source](https://cursor.com/docs/agent/hooks)
- `sessionStart`: `session_id`, `is_background_agent`, `composer_mode`; out `env` (applies to later hooks in session) and `additional_context`; "Fire-and-forget". `sessionEnd`: `reason` (`completed`/`aborted`/`error`/`window_close`/`user_close`), `duration_ms`, `final_status`, `error_message` — [Source](https://cursor.com/docs/agent/hooks)
- `preCompact`: `trigger` (`auto`/`manual`), `context_usage_percent`, `context_tokens`, `context_window_size`, `message_count`, `messages_to_compact`, `is_first_compaction`; out `user_message`; observational — [Source](https://cursor.com/docs/agent/hooks)
- `workspaceOpen`: input omits conversation fields; out `pluginPaths` (array of absolute paths) — "Can return plugin paths to load when a workspace opens" — [Source](https://cursor.com/docs/agent/hooks); [Source](https://cursor.com/docs/plugins)
- Matcher targets: `preToolUse`/`postToolUse`/`postToolUseFailure` match `tool_name` ∈ `Shell`, `Read`, `Write`, `Grep`, `Delete`, `Task`, or `MCP:<tool_name>`; `subagentStart`/`subagentStop` match subagent type (`generalPurpose`, `explore`, `shell`, …); `beforeShellExecution` matches the command string; `beforeReadFile`→`Read`; `afterFileEdit`→`Write`; `beforeTabFileRead`→`TabRead`; `afterTabFileEdit`→`TabWrite`; `beforeSubmitPrompt`→`UserPromptSubmit`; `stop`→`Stop`; `afterAgentResponse`→`AgentResponse`; `afterAgentThought`→`AgentThought` — [Source](https://cursor.com/docs/agent/hooks)
- Env vars: `CURSOR_PROJECT_DIR`, `CURSOR_VERSION`, `CURSOR_USER_EMAIL`, `CURSOR_TRANSCRIPT_PATH`, `CURSOR_CODE_REMOTE` (`"true"` in remote workspaces), `CLAUDE_PROJECT_DIR` ("alias … for Claude compatibility") — [Source](https://cursor.com/docs/agent/hooks)
- Cloud-agent support: runs in cloud = `beforeShellExecution`, `afterShellExecution`, `beforeReadFile`, `afterFileEdit`, `preToolUse`, `postToolUse`, `postToolUseFailure`, `subagentStart`, `subagentStop`, `beforeSubmitPrompt`, `preCompact`, `afterAgentResponse`, `afterAgentThought`, `stop`; NOT in cloud = `sessionStart`, `sessionEnd`, `beforeMCPExecution`, `afterMCPExecution`, `beforeTabFileRead`, `afterTabFileEdit`, `workspaceOpen`; "User-level hooks are not loaded" by cloud agents — [Source](https://cursor.com/docs/agent/hooks)
- New since 3.11 (payload only): 3.22 `parent_tool_call_id` on `preToolUse`/`postToolUse`/`postToolUseFailure`, `child_conversation_id` on `subagentStop`; 3.24 `tool_use_id` on shell and MCP hooks "matching `preToolUse`", `transcript_path` set when a transcript exists; 3.23 Windows extensionless script resolution; 3.19 `beforeMCPExecution` receives server command/URL — [Source](https://cursor.com/docs/release-notes)
- Plugin hooks in the CLI: "Hooks from installed plugins, including `--plugin-dir` plugins, now run" (v2026.08.11) — [Source](https://cursor.com/docs/cli/changelog)

### Inferences
- `parent_tool_call_id` (3.22) is exactly the field the repo's `cursor-agent-tools-guard.sh` lacked when it had to reconstruct subagent membership from event order; a guard targeting ≥3.22 can key on it directly (inferred from the field name; the release note gives no semantics beyond the name).
- `tool_use_id` now spanning `preToolUse` and the shell/MCP hooks (3.24) lets one correlate a `preToolUse` decision with the matching `beforeShellExecution`/`beforeMCPExecution` call.

### Gaps
- The hooks doc gives no numeric default for `timeout` ("platform default").
- No source states whether `parent_tool_call_id` is empty/absent at top level versus populated only inside a `Task`.

## KQ3: Does Cursor support skills frontmatter beyond name/description?

### Takeaway
Yes: `paths` (globs; legacy `globs` fallback), `disable-model-invocation`, `icon`, `color`, `metadata` are documented, and `user-invocable: false` is supported in the CLI per its changelog though absent from the skills doc; `allowed-tools`, `license`, `compatibility` are not documented.

### Cited Findings
- `name` (required; "Lowercase letters, numbers, and hyphens only. Must match the parent folder name"), `description` (required), `paths` ("Glob patterns that scope the skill to matching files. Accepts a comma-separated string or a list"), `disable-model-invocation` ("only included when explicitly invoked via `/skill-name`"), `icon` (Custom Mode badge), `color` (`default`, `green`, `cyan`, `blue`, `purple`, `magenta`, `orange`, `yellow`, `red`, `brand`), `metadata` ("Arbitrary key-value mapping") — [Source](https://cursor.com/docs/context/skills)
- "The legacy `globs` field is still accepted as a fallback for older skills, but new skills should use `paths`" — [Source](https://cursor.com/docs/context/skills)
- Locations: `.agents/skills/`, `.cursor/skills/`, `~/.agents/skills/`, `~/.cursor/skills/`; compatibility loads from `.claude/skills/`, `.codex/skills/`, `~/.claude/skills/`, `~/.codex/skills/`; nested `SKILL.md` anywhere under the root; a skills folder inside a nested project dir "is scoped to files in that directory" — [Source](https://cursor.com/docs/context/skills)
- Optional dirs `scripts/`, `references/`, `assets/`; invocation automatic, manual via `/` ("attaches to one message"), or session-long as a Custom Mode via Option+Enter / Alt+Enter; `/migrate-to-skills` built in since 2.4 — [Source](https://cursor.com/docs/context/skills)
- CLI v2026.07.06: "`user-invocable: false` hides skills from slash commands" — [Source](https://cursor.com/docs/cli/changelog)
- CLI v2026.10.08: `/skills` flags "skills that exceed Agent Skills limits (name length and format, folder mismatch, description and body size)" — [Source](https://cursor.com/docs/cli/changelog)
- Plugin-side: Skills discovered as "Each subdirectory containing `SKILL.md`" under `skills/`; a root `SKILL.md` counts "Only if no `skills/` directory and no manifest `skills` field" — [Source](https://cursor.com/docs/reference/plugins)
- Agent Plugins spec validates each SKILL.md "against the Agent Skills specification" — [Source](https://agent-plugins.org/plugin-authors)

### Inferences
- Cursor's skill schema is a superset of the portable name/description pair; the repo's portable schema stays valid, and `disable-model-invocation`/`user-invocable` map 1:1 to the Claude flags.

### Gaps
- No page documents `allowed-tools`, `effort`, `context`, `agent`, `license`, or `compatibility`; whether unknown keys are ignored or warned about is unstated (the v2026.10.08 `/skills` warnings only cover name/folder/size).
- `user-invocable` is not in the skills doc; only the CLI changelog mentions it, so desktop support is unverified.

## KQ4: Do Cursor plugins support agents, commands, MCP, rules in the manifest? Fields?

### Takeaway
Yes — `.cursor-plugin/plugin.json` takes `rules`, `agents`, `skills`, `commands` (string or array), `hooks` (path or inline object), `mcpServers` (string/object/array) and a `variables` JSON-Schema for dashboard-set secrets; a parallel root `plugin.json` "Agent Plugins" format covers only skills + MCP. Submission is Git-repo based, open-source, manually reviewed per update.

### Cited Findings
- Required: `name` ("Lowercase, kebab-case … alphanumerics, hyphens, and periods … start and end with an alphanumeric"). Optional: `description`, `version` (semver), `author` {`name` required, `email`}, `homepage`, `repository`, `license`, `keywords`, `logo` (relative path or http(s) URL), `rules` (string|array), `agents` (string|array), `skills` (string|array), `commands` (string|array), `hooks` (string|object: "Path to a hooks config file, or inline config"), `mcpServers` (string|object|array: "Overrides default `mcp.json` discovery"), `variables` (object: "A JSON Schema of variable names. Values are set in the dashboard") — [Source](https://cursor.com/docs/reference/plugins)
- Official template also uses `displayName` (not in the reference) — [Source](https://raw.githubusercontent.com/cursor/plugin-template/main/plugins/starter-advanced/.cursor-plugin/plugin.json); README says "set `name` (lowercase kebab-case), `displayName`, `author`, `description`, `keywords`, `license`" — [Source](https://github.com/cursor/plugin-template)
- Default discovery: `skills/` (subdirs with `SKILL.md`), `rules/` (`.md`, `.mdc`, `.markdown`), `agents/` (`.md`, `.mdc`, `.markdown`), `commands/` (`.md`, `.mdc`, `.markdown`, `.txt`), `hooks/hooks.json` ("Parsed for event names"), `mcp.json` ("Parsed for server entries"); "A manifest path for a component type replaces folder discovery for that type" — [Source](https://cursor.com/docs/reference/plugins)
- Agents format in plugins: frontmatter `name` (kebab-case), `description` only. Commands: optional frontmatter `name`, `description` — [Source](https://cursor.com/docs/reference/plugins)
- Plugin hooks: `hooks/hooks.json` top-level `hooks` object → event → entries with `command` and optional `matcher` (e.g. `"matcher": "rm|curl|wget"`) — [Source](https://cursor.com/docs/reference/plugins)

## KQ5: What are Remote Control, Rollouts, Security Review — anything a plugin can use?

### Takeaway
All three are account/dashboard features with no plugin hook: Remote Control is a device-pairing/handoff feature with a `/remote-control` command and Settings toggle; Rollouts is an Automations bot configured in the dashboard with a deployment-reporting API; Security Review is an Automations bot whose only extension point is "tools and MCPs".

### Cited Findings
- Remote Control docs: "The agent loop moves to the cloud while its tools keep running on your machine"; requires "Cursor 3.9.8 or later"; enable under Settings > Agents; `/remote-control` command hands the session off; not available when privacy settings disable cloud storage; "Every tool call … runs on your computer"; mobile-started agents tagged `source: iosApp`; docs list "no API, hooks, or specific settings keys" — [Source](https://cursor.com/docs/cloud-agent/mobile)
- Remote Control Oct 6 post adds iOS pairing, on-by-default except Enterprise, "Keep this computer awake"; 3.24 "Local agents can be added to cloud Projects through Remote Control" — [Source](https://cursor.com/changelog/remote-control-local-agents); [Source](https://cursor.com/docs/release-notes)
- Rollouts docs: "monitors each pull request from review to production"; "available on Teams and Enterprise plans"; config lives in the Automations UI (no repo file); watches "Origin, GitHub, GitLab.com, and Bitbucket Cloud"; checks "at deploy time and again after 20 minutes, 1 hour, 1 day, and 3 days"; deploy API endpoints `CreateEnvironment`, `CreateService`, `CreateDeployment`, `AppendDeploymentEvent` under `factory.v1.DeploymentsService` on `api.cursor.com`, token via `api2.cursor.sh/auth/exchange_user_api_key`; "A failed report must never fail the deploy"; data sources include "MCP connections" — [Source](https://cursor.com/docs/rollouts)
- Security agents docs: "Security Reviewer: checks pull requests before they merge"; "Vulnerability Scanner: scans the codebase at rest"; both "run on Automations and require Cloud Agents"; "A Security Reviewer must have at least one tool or MCP before you can save it"; no repo config file; `/review` and `/review-security` "run in Cursor 3.7+, at cursor.com/agents, and in the Cursor CLI"; Bitbucket/Azure DevOps unsupported — [Source](https://cursor.com/docs/security-agents)
- Changelog: "Team rules … Security Review enforces them on every PR"; "Dismissing a finding with a reason stops it from being raised again on that PR" — [Source](https://cursor.com/changelog/rollouts-and-security-reviewer); Week of Oct 5 split "Security Reviewer and Vulnerability Scanner" pages, "Incomplete security reviews no longer auto-approve" — [Source](https://cursor.com/docs/release-notes)
- Origin apps (not plugins) are the new third-party integration surface for PR checks: "Apps use an app JWT and installation access tokens, receive webhook events, and write check runs, PR comments, and reviews" — [Source](https://cursor.com/changelog/origin-app-marketplace)

### Inferences

- No source says whether Remote Control fires any hook event (`sessionStart` `is_background_agent` is the closest documented signal).

## KQ7: Third-party (Claude Code) import, and which Claude Code features have no Cursor equivalent

### Takeaway
Cursor imports Claude hooks only from `.claude/settings.local.json`, `.claude/settings.json`, `~/.claude/settings.json` (8 of 10 events mapped; `Notification`/`PermissionRequest` dropped; `Glob` unsupported), plus skills from `.claude/skills` and agents from `.claude/agents`; it never reads a Claude plugin's own `hooks.json`. No equivalents exist for mods, output styles, statusline-as-plugin, `StopFailure`, `DirectoryAdded`, `WorktreeCreate/Remove`, `PreModelSwitch`, `PermissionRequest`, `Notification`, plugin `userConfig`, `${CLAUDE_PLUGIN_DATA}`, or `claude plugin validate/test/eval`.

### Cited Findings
- Toggle "Include Third-Party Plugins, Skills, and Other Configs" under Cursor Settings → Agents → Third-Party Imports, on by default; paths read: `.claude/settings.local.json` > `.claude/settings.json` > `~/.claude/settings.json`; merge order Enterprise → Team → `.cursor/hooks.json` → `~/.cursor/hooks.json` → Claude sources; "All matching hooks from every source run" — [Source](https://cursor.com/docs/reference/third-party-hooks)
- Mapping: `PreToolUse`→`preToolUse`, `PostToolUse`→`postToolUse`, `UserPromptSubmit`→`beforeSubmitPrompt`, `Stop`→`stop`, `SubagentStop`→`subagentStop`, `SessionStart`→`sessionStart`, `SessionEnd`→`sessionEnd`, `PreCompact`→`preCompact`; `Notification` and `PermissionRequest` unsupported — [Source](https://cursor.com/docs/reference/third-party-hooks)
- Tool names: "`Bash` maps to `Shell`, and `Edit` maps to `Write`. `Read`, `Write`, `Grep`, `Task`, `WebFetch`, and `WebSearch` keep their names. `Glob` is not supported" — [Source](https://cursor.com/docs/reference/third-party-hooks)
- Output translation: `hookSpecificOutput.permissionDecision`→`permission`, `permissionDecisionReason`→`user_message`, `updatedInput`→`updated_input`; Stop/SubagentStop `decision:"block"`+`reason` = follow-up; exit 0/2/other semantics identical; limits: `subagentStart` native-only, `loop_limit` native-only, dashboard distribution not via Claude files — [Source](https://cursor.com/docs/reference/third-party-hooks)
- Skills loaded from `.claude/skills/` and `~/.claude/skills/`; agents from `.claude/agents/` and `~/.claude/agents/` — [Source](https://cursor.com/docs/context/skills); [Source](https://cursor.com/docs/agent/subagents)
- `${CLAUDE_PLUGIN_ROOT}` expanded in Agent Plugins' `mcp.json`; `${PLUGIN_DATA}` not expanded — [Source](https://cursor.com/docs/reference/plugins)
- `CLAUDE_PROJECT_DIR` alias always set for hooks — [Source](https://cursor.com/docs/agent/hooks)
- Cursor's own `hooks.json` and the plugin reference enumerate exactly 21 events; none named `StopFailure`, `Notification`, `PermissionRequest`, `DirectoryAdded`, `WorktreeCreate`, `WorktreeRemove`, `PreModelSwitch`, `PostModelSwitch` — [Source](https://cursor.com/docs/agent/hooks); [Source](https://cursor.com/docs/reference/plugins)
- Cursor plugins "are largely markdown files … No binaries are shipped" — the review posture precludes in-process code modules — [Source](https://cursor.com/help/security-and-privacy/marketplace-security)

### Inferences
- Claude→Cursor coverage for this repo's `hooks/hooks.json`: `PreToolUse`, `PostToolUse`, `UserPromptSubmit`, `Stop`, `SubagentStop`, `SessionStart`, `SessionEnd` would import *if* they were declared in a `.claude/settings*.json`; `StopFailure`, `Notification`, `DirectoryAdded`, `WorktreeCreate`, `WorktreeRemove` have no target. The Cursor-format bundle remains the only way to get plugin-shipped hooks to run (unchanged since the repo's Sep 23 measurement, and reinforced by the CLI note that plugin hooks run from `--plugin-dir`).
- Native-only Cursor events a plugin could newly exploit that Claude lacks: `beforeReadFile`, `afterFileEdit`, `beforeMCPExecution`/`afterMCPExecution`, `postToolUseFailure`, `subagentStart`, `afterAgentThought`, `workspaceOpen` (→ `pluginPaths`), `beforeTabFileRead`/`afterTabFileEdit`.

### Gaps
- No page states whether Cursor reads `.claude-plugin/plugin.json` (Claude plugin manifests) at all; only the Agent Plugins root `plugin.json` and Cursor's `.cursor-plugin/plugin.json` are documented. Treat Claude-manifest import as unsupported until measured.
- Whether `CLAUDE.md` is read as project instructions is unstated (the rules page names only `.cursor/rules` and `AGENTS.md`).
