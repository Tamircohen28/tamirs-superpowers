## Key question 1: What is a mod, what is the hooks-module format, and where do mods run (including built-in mods)?

### Takeaway
A mod is an ordinary plugin whose `hooks/hooks.json` has a `modules` key naming one ES-module file that exports `register(on, options)`; its hooks run inside Claude Code's process in every session kind, but only the terminal, the Desktop Code tab and (since 2.1.299) the VS Code chat panel draw what a mod draws. Mods are on by default from 2.1.287 (Desktop 2.1.286), and six built-in mods ship with the CLI.

### Cited Findings
- Definition: "A mod is a plugin that changes how Claude Code looks and behaves. It's made of JavaScript or TypeScript event handlers... the handler can watch the event, change it, or take it over." Claude Code calls both settings-file hooks and mod handlers "hooks"; docs call the settings-file kind "settings hook". — [OV](https://code.claude.com/docs/en/plugins/mods)
- Files (official table): `.claude-plugin/plugin.json` (required; "Mods add no required fields"); `hooks/hooks.json` (required; "`modules`: an array with one path, relative to this file, to the hooks module, as in `"modules": ["./register.js"]`. Can also hold settings hooks under `hooks`"); the hooks module (required; "Exports `register(on, options)`. Named `.js`, `.mjs`, `.cjs`, `.jsx`, `.ts`, `.mts`, `.cts`, or `.tsx`. An ES module"); `types/index.d.ts` named by `types` in the manifest ("When the mod uses `$.state` or adds a namespace to the mods API"); files ending `.test.ts`/`.test.tsx` (optional, run by `claude plugin test`). — [REF](https://code.claude.com/docs/en/plugins/mods/reference)
- "`options` holds the values of the `userConfig` fields the manifest declares, with defaults filled in." — [REF](https://code.claude.com/docs/en/plugins/mods/reference)
- Module environment: "The module runs in an environment of its own, with no DOM and no Node: everything outside it is reached through `$`. JSX is available with `h` as the factory." A module holding `import()` does not load; there is no `require`. Globals available: `h`, `Fragment`, the JSX namespace, and web APIs (URL, TextEncoder, AbortController, crypto.subtle). — [SKILLREF]; [LOCALDTS header]
- Official limit list: "The hooks module itself has no Node.js APIs, no timer globals such as `setTimeout`, and no network or file access of its own." Imports: "Import only from files inside the plugin directory, by relative path. The one bare import allowed is `claude-code`." — [API](https://code.claude.com/docs/en/plugins/mods/api); [CREATE](https://code.claude.com/docs/en/plugins/mods/create)
- Version gate: "Mods are on by default. In the terminal, use Claude Code v2.1.287 or later. The Desktop app includes its own copy of Claude Code, and mods work there from v2.1.286." `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS` is ignored from 2.1.287 ("setting it to `0` doesn't keep mods off"). — [OV](https://code.claude.com/docs/en/plugins/mods)
- Changelog 2.1.287: "Added Claude Mods: plugins may now modify deeper behavior" and "Added You should know, a built-in mod where a side agent watches your back... Turn it on with `/plugin enable cc-plugin-you-should-know@builtin`". — [CL](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)
- Where mods run (official table): terminal incl. JetBrains — hooks yes, draws yes; Desktop Code tab (not WSL) — yes/yes "except elements the elements table marks terminal-only"; Desktop WSL session — no/no ("plugins aren't available in WSL sessions"); VS Code chat panel — hooks yes, draws "with extension version 2.1.299 or later, in a session that fetches feature flags"; `claude -p` and Agent SDK — hooks yes, draws no; Remote Control from claude.ai/mobile — hooks run "in the session on your machine", drawing appears "In the terminal on your machine"; cloud session — hooks yes "for a plugin that reaches the cloud session", draws no. Hooks run "whichever provider serves the model, including Amazon Bedrock, Google Cloud's Agent Platform, and Microsoft Foundry." — [OV](https://code.claude.com/docs/en/plugins/mods)
- Turning mods off: one mod via `/plugin` Installed tab; every installed mod for one session via `--safe-mode` ("which also disables your other customizations"); every mod you installed in every session via `"disableAllHooks": true` in `~/.claude/settings.json` (also stops settings hooks and custom status line; "What your organization manages keeps running"). `disableAllHooks` and `allowManagedModsOnly` "stop a mod and leave the rest of its plugin in place: the plugin stays installed, and its skills, commands, agents, and MCP servers load." `--bare` also stops installed mods. "The settings and flags that stop installed mods, such as `disableAllHooks`, `--bare`, and `--safe-mode`, don't stop built-in mods." — [OV](https://code.claude.com/docs/en/plugins/mods)
- `/plugin` shows "a dim line under the tabs" like `1 mod active · first-mod`; this line "omits built-in mods". — [OV](https://code.claude.com/docs/en/plugins/mods)
- Built-in mods (official table, by `/plugin` name): `cc-plugin-agents-md` (loads `AGENTS.md` as project instructions; every session apart from those that can't read AGENTS.md; disable in `/plugin` or choose which instruction files load); `cc-plugin-diff` (takes over `/diff` and draws its pane; interactive terminal sessions; disabling leaves the built-in `/diff`); `cc-plugin-plugin-authoring` (gives Claude the `plugin-authoring` skill; "It holds a skill and no mod code"); `cc-plugin-sec-default` (guards what the org manages from user-installed mods; "You can't" turn it off — admin sets the order); `cc-plugin-telemetry` (sends analytics records; off with `DISABLE_TELEMETRY`); `cc-plugin-you-should-know` (side agent note above the prompt; off until turned on). — [OV](https://code.claude.com/docs/en/plugins/mods)
- Public source of built-ins in `mods/` of anthropics/claude-code: `diff` ("buttons bound to keyboard actions and scrolling the mod handles itself"), `agents-md` (one `userConfig` option with values `claude-md-or-agents-md` (default), `claude-md-and-agents-md`, `managed-only`, `claude-md`), `sec-default` ("a model for a mod that enforces policy"; "runs outermost on machines with managed settings or a `managed-mcp.json`, or for Team or Enterprise organizations"), `telemetry` ("adds methods that other mods can call, and ships their types"; "refuses installed plugins and sends nothing when Claude Code's analytics are off"), plus `types/` ("Shared TypeScript declarations... written by `/plugin-types`") and `tsconfig.json`; each mod has `tests/`, typecheck with `tsc -p mods/tsconfig.json`, run from source with `claude --plugin-dir mods/diff`. README caveat: "These mods are not listed in this repository's marketplace." — [OV](https://code.claude.com/docs/en/plugins/mods); [MODSRC](https://github.com/anthropics/claude-code/tree/main/mods)
- Binary strings in the installed 2.1.302 CLI (`strings /opt/claude-code/bin/claude`) also contain the built-in plugin ids `cc-plugin-claude-test`, `cc-plugin-easel`, `cc-plugin-mermaid`, `cc-plugin-mods-guide`, `cc-plugin-responsive-mode`, `cc-plugin-tips` beside the six documented ones — local observation, undocumented. — local observation (binary strings), not an official source
- Comparison table (official): mod can change "Tool calls, prompts, commands, turns, and what the interface draws" and can draw; settings hook "Whether a tool call or prompt goes ahead, a tool call's arguments and result, and context added for Claude", cannot draw; skill = Markdown instructions; MCP = external tools. "A plugin can hold all of them." — [OV](https://code.claude.com/docs/en/plugins/mods)
- Chain ordering of settings hooks: "`PreToolUse` hooks from managed settings run before the first mod's `tool.call` hook, and a block from one of them is final"; other `PreToolUse` hooks (other settings files and plugins' `hooks/hooks.json`) "run after the last mod calls `next`... A mod that answers `tool.call` without calling `next` keeps them from running". — [EV](https://code.claude.com/docs/en/plugins/mods/events)
- Hot reload: `--plugin-dir` folder is watched in interactive sessions; "saving a file reloads the hooks module, so `register` runs again in a fresh environment and the previous environment's timers are dropped." Saves made during the model's own turn reload once when the turn ends "or sooner when a tool or command the plugin registered is about to run"; other saves reload "once the folder has been quiet: a lone save within a quarter second". `claude -p` always loads fresh; long-lived headless/SDK/desktop sessions watch when `CLAUDE_CODE_PLUGIN_DIR_WATCH=1`. `CLAUDE_CODE_PLUGIN_DIRS` (path-list separated; `~` allowed; from env or `env` block of `~/.claude/settings.json`, never project settings) loads folders where no flag can be given (Desktop, SDK). — [SKILLREF]; [REF](https://code.claude.com/docs/en/plugins/mods/reference)
- Claude-written mods: Claude writes to `~/.claude/dev-mods/<session-id>/<mod>/`; on first save Claude Code asks to enable hot reloading ("Enable for this session" / "Not now"); such mods load only in that session and the folder is deleted after `cleanupPeriodDays`; they can't load in `claude -p`, `dontAsk` mode, untrusted workspaces, `--safe-mode`/`--bare`, `disableAllHooks`, or when managed settings block them. — [CREATE](https://code.claude.com/docs/en/plugins/mods/create)
- Hooks worker: "Installed mods share one worker thread." A mod that crashes it is unloaded (`<mod> was unloaded: it crashed the hooks worker`); if the worker crashes 3 times untraceably, every non-built-in mod is unloaded until `/reload-plugins` (`hooks: mods that run in the hooks worker are off for this session: it crashed 3 times`). — [TS](https://code.claude.com/docs/en/plugins/mods/troubleshoot)
- Debug log line for a loaded mod: `hooks module first-mod@inline loaded (worker, environment 2, tier user); events: session.start,tool.call,command.run,ui.render`. — [TS](https://code.claude.com/docs/en/plugins/mods/troubleshoot)

### Inferences
- "Draws on Claude Desktop" is officially yes for the Code tab (non-WSL), with `e.surface === 'desktop'` and a Desktop element table that lacks `Raster`/`Image` but has `Svg` (see Q3). Desktop can't take `--plugin-dir`; the documented loading routes are a marketplace install or `CLAUDE_CODE_PLUGIN_DIRS`.
- The six extra `cc-plugin-*` names in the 2.1.302 binary suggest more built-in mods exist (or are staged behind flags) than the docs list; treat as unconfirmed.

### Gaps
- No official statement of whether Codex CLI (which loads the same `hooks/hooks.json`) tolerates the `modules` key; this repo's own `docs/engineering/architecture/mods.md` records it as unverified.
- The docs reference page says it is current to 2.1.290 (CLI/Desktop); the 2.1.291–2.1.302 changes are known only from the CHANGELOG (Q7).

## Key question 2: What is the full list of `$` namespaces/methods and hookable events, with signatures?

### Takeaway
`$` has 22 namespaces (plus surface element tables) and roughly 70 methods; the event set has ~45 engine events plus `classic.<SettingsHookEvent>`, `telemetry.*`, and one event per `$` method (so a mod earlier in the chain can intercept any other mod's call). Every hook is `($, e, next)`; `turn.step` and `process.spawn` hooks are async generators.

### Cited Findings
**Hook function contract**
- `on(event, matcher?, hook)` returns a registration with `.catch(handler)`. Args: `$` (mods API; "Write each call in full, namespace then method"), `e` ("deeply frozen plain data"), `next(e)` (middleware; resolves to the event's result), `next.signal` (AbortSignal), `next.origin` (`{ plugin, tier }`; engine is `{ plugin: 'engine', tier: 'core' }`; tiers `prepend`, `user`, `append`, `builtin`), `next.budget` (`.ms`, `.remainingMs`), `next.to(e, tier)` (skip to `append`/`builtin`/`core`; only a mod in `prependPlugins`/`appendPlugins` may call it), `next.error` (in `.catch` only: `kind` = `throw` | `timeout` | `re-entry` (2.1.292+); `next.error.cause` = `rewritten` (2.1.300+) | `lent` (2.1.292+)), `next.called`. — [REF](https://code.claude.com/docs/en/plugins/mods/reference)
- Matchers: "an object whose fields are compared with the event's... A field can be a value, an array of allowed values, or a regular expression"; e.g. `{ tool: /^mcp__github__/ }`. `'classic.*'` wildcard; `'*'` matches every event except telemetry. "Register each event once per matcher. If you call `on` twice for `session.start` with no matcher, the module fails to load with `on("session.start") is registered twice without a matcher`." — [EV](https://code.claude.com/docs/en/plugins/mods/events)
- Three behaviours: observe (`return next(e)`), rewrite (`next({ ...e, text })`), answer (return a result without `next`). — [EV](https://code.claude.com/docs/en/plugins/mods/events)

**Events (official reference tables, exact names; what a hook can return)**
- Tools: `tool.call` (tool about to run; `next(e)`, `{ deny: reason }`, or `{ result }`; also `{ deny }` after `await next(e)` withholds the result; retry by calling `next(e)` again); `tool.check` (decision after rules/permission mode/`tool.call`/`PreToolUse`; returns `{ decision }` = `allow`|`ask`|`deny` (+`reason`); fields `e.agentId`, `e.ceiling` require 2.1.290+); `tool.describe` (once per tool when description first sent; again for MCP tool loaded via tool search; returns `{ description }` optionally with `isDeferred` true/false). — [REF](https://code.claude.com/docs/en/plugins/mods/reference); [EV](https://code.claude.com/docs/en/plugins/mods/events)
- Prompts: `prompt.submit` (`next({ ...e, text })`, `next({ ...e, context })`, or `{ drop: reason }`; dropped text goes back into the prompt box with "Prompt dropped by a hook:"); `prompt.fill`, `prompt.suggest` (`next(e)` with changed text); `prompt.edit` (`next(e)`; 50 ms budget); `prompt.autocomplete` (`e.token`; returns `{ suggestions }` of `{ text, label, description }`; added 2.1.292); `prompt.compose` (`{ sections }` list of `{ id, text, scope }`); `prompt.section` (`e.name`; `{ text }` or `{ text: null }`); `prompt.context` (`{ blocks }`, once per conversation); `prompt.attachment` (`e.type`, `e.detail`; `{ text }`/`{ text: null }`); `prompt.mention` (`next({ ...e, path })` or `{ deny }`; 2.1.290+); `skill.prompt` (`{ text }`; fields `e.source`, `e.pluginName`, `e.path`, `e.frontmatter`, `e.frontmatterProblem` require 2.1.299+); `attribution.text` (`{ text }`; matcher e.g. `{ kind: 'commit' }` per local validate output); `prompt.change` (2.1.300: "raised when the prompt box's text changes without a typed edit"). — [REF](https://code.claude.com/docs/en/plugins/mods/reference); [CL](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)
- Commands/config: `command.run` (`{ text }`, `{}`, or `next(e)`; `e.args`; result may carry `{ text, context? }` where `context` is model-only notes); `command.describe` (`{ description, argumentHint, isHidden }`); `config.set` (`next({ ...e, value })` or `{ deny }`); `config.describe` (`{ label, description, isHidden }`). — [REF](https://code.claude.com/docs/en/plugins/mods/reference); [SKILLREF]
- Turns: `turn.start` (`next(e)`; `e.turnId`; since 2.1.299 "also hear[s] subagents' and teammates' turns"); `turn.step` (async generator; `yield* next(e)`, `next({ ...e, model })`, `next({ ...e, effort })`; result has `usage` {input_tokens, output_tokens, cache_read_input_tokens, cache_creation_input_tokens, model} and `serverToolUses` (2.1.290+)); `turn.complete` (`next(e)` or `{ text }` shown under the answer; `e.answer`, `e.durationMs`, `e.usage`, `e.isAborted`, `e.agentId`). — [REF](https://code.claude.com/docs/en/plugins/mods/reference); [EV](https://code.claude.com/docs/en/plugins/mods/events)
- Session: `session.start` ("Once for each loaded mod, before the first prompt, and again after a reload... Not after `/clear`, `/resume`, or `/branch`"); `session.end` (`e.reason` ∈ `clear`, `resume`, `logout`, `prompt_input_exit`, `other`; `/branch` reports `resume`); `session.compact` (`{ skip: reason }`; the skill reference says its result carries a `ModelUsage`); `session.receive` (`{ consumed: reason }`), `session.send` (`{ isDelivered: false, reason }`); `session.append` (`next({ ...e, message })` with changed `message.content`; `e.door` ∈ `prompt`, `command`, `response`, `tool-result`, `tool-message`, `delivery`, `attachment`, `hook-context`, `note`, `compaction`, `notice`, plus `queue` (2.1.299)); `session.attach`/`session.detach`; `session.measure` ("After each turn, and when a plan limit's percent used changes"). — [REF](https://code.claude.com/docs/en/plugins/mods/reference); [SKILLREF]; [CL](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)
- Subagents: `agent.offer` (`{ isOffered: false }`); `agent.spawn` (`next({ ...e, model })` or `{ deny }`; `e.isTeammate` for teammates (2.1.289+); workflow agents with run/index (2.1.292); rewriting a workflow agent's `prompt` and `model` (2.1.300); "When Claude resumes a subagent with the SendMessage tool, your `agent.spawn` hook doesn't run again"). — [REF](https://code.claude.com/docs/en/plugins/mods/reference); [CL](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)
- Interface: `ui.render`, `ui.resolve` ("once for each app, render site, and mod"), `ui.press`/`ui.input`/`ui.select`, `ui.focus`/`ui.scroll`, `ui.close` (`e.id`, `e.origin.kind` ∈ `plugin`, `person`, `unload`), `ui.message` (Client posts data), `ui.fault` (`e.phase` ∈ `load`, `render`, `run`; 2.1.289+), `ui.copy` (per skill reference). — [REF](https://code.claude.com/docs/en/plugins/mods/reference); [SKILLREF]
- Other mods: `plugin.register` (`e.uses` lists events/calls/env/state "as `claude plugin validate` prints them"; `e.tier`; return `{ refuse: reason }`); `engine.create` (return a changed mods API to add a namespace; a non-`user`-tier mod can also withhold one). — [REF](https://code.claude.com/docs/en/plugins/mods/reference)
- Telemetry: `telemetry.log`, `telemetry.mark` — a user-installed mod must pass `{ to: 'collector' }` or it "fails `claude plugin validate`"; streams are `collector` (customer OTel collector) and `anthropic`. — [REF](https://code.claude.com/docs/en/plugins/mods/reference); [SKILLREF]
- Settings-hook events: `classic.<Event>` (`classic.Stop`, `classic.PostToolUse`, `classic.SessionStart` with `e.source` ∈ `clear`/`resume`/`fork`…); "`e` is the hook's stdin JSON" incl. `transcript_path`. `classic.PreToolUse` is raised by `$.tool.call` beneath every plugin's `tool.call` hook. — [REF](https://code.claude.com/docs/en/plugins/mods/reference); [SKILLREF]
- Mods-API-call events: "Every mods API method is also an event, named for its namespace and method, such as `fs.read`, `model.complete`, or `ui.open`. A hook on one intercepts calls from the mods that run after it, and can return `next(e)`, `{ deny: reason }`, or `{ value }`." `state.set` is such an event (another plugin changes your state by hooking it with a matcher on `plugin`/`key`). `process.spawn` as an event streams (async generator). — [REF](https://code.claude.com/docs/en/plugins/mods/reference); [SKILLREF]
- Event result keys enumerated in the 2.1.288 `claude-code.d.ts` `EngineResultOf` type (verbatim list): `agent.offer agent.spawn attribution.text command.describe command.run config.describe config.set engine.create plugin.register prompt.attachment prompt.compose prompt.context prompt.edit prompt.fill prompt.section prompt.submit prompt.suggest session.append session.attach session.compact session.detach session.end session.measure session.receive session.send session.start skill.prompt telemetry.log telemetry.mark tool.call tool.check tool.describe turn.complete turn.start turn.step ui.focus ui.input ui.message ui.press ui.render ui.resolve ui.scroll ui.select` (so `ui.close`, `ui.fault`, `prompt.autocomplete`, `prompt.mention`, `prompt.change` post-date 2.1.288). — [LOCALDTS]

**`$` namespaces and methods (official reference table, 2.1.290-era, cross-checked with the 2.1.288 d.ts which lists the same nouns)**
- `$.plugin`: `name`, `root` (2.1.288 d.ts additionally types `provenance`, `tier`, `uses`, `version` on a `PluginNoun`). — [REF](https://code.claude.com/docs/en/plugins/mods/reference); [LOCALDTS]
- `$.ui`: `resolve`, `invalidate`, `open`, `close`, `panes`, `focus`, `scroll`, `toast`, `status`, `log`, `notice`, `ask`, `copy`, `selection` (2.1.288+), `blit`; plus `$.ui.notify` (2.1.295: "raises a native notification through your own notification setting") and `$.ui.view({ agentId })` (2.1.300: "shows an agent's transcript in the main view"). — [REF](https://code.claude.com/docs/en/plugins/mods/reference); [CL](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)
- `$.command`: `register`, `run`, `list`. `$.command.register({ name, description, argumentHint?, immediate? })`; "throws for a taken name, with a message such as `"/focus" refused: it is the built-in /focus`". — [REF]; [API](https://code.claude.com/docs/en/plugins/mods/api)
- `$.tool`: `register`, `call`, `check`, `list`. `$.tool.register({ name, description, inputSchema, isDeferred? })`; listed as `mcp__<plugin>__<name>`; `isDeferred` requires 2.1.293+. — [API](https://code.claude.com/docs/en/plugins/mods/api); [CL]
- `$.agent`: `register`, `spawn`, `list` (statuses `pending`, `running`, `waiting`, `idle`, `completed`, `failed`, `killed`; `idle`/`waiting` 2.1.289+). `$.agent.register` takes "an agent definition as settings JSON spells one"; registered as `<plugin>:<name>`; `$.agent.spawn({ subagentType })` "runs one and its answer is its `turn.complete`". — [REF]; [SKILLREF]
- `$.model`: `complete`, `fork`, `classify`. `complete({ model, prompt, system?, maxTokens?, timeoutMs?, effort? })` → `ModelCompleteResult` (`isAnswered` + `text` + `usage`, or `isAnswered: false` with `reason` ∈ `api-error` (with `status`, `error`), `empty-reply`, `aborted`); `prompt`/`system` may be arrays of `{ text, cache?: true }` blocks for cache breakpoints (2.1.292+); `fork({ prompt })` reuses the conversation's last request (extra reason `nothing-to-fork`). — [API]; [SKILLREF]
- `$.prompt`: `submit`, `read`, `fill`, `suggest`, `compose`; `submit({ text, asUser?: true })` "queues a prompt that starts a turn of its own once the session is idle... the call resolves as that turn starts"; `fill({ text, mode: 'insert' })`; `$.prompt.media` (2.1.299, managed-settings mods only). — [REF]; [SKILLREF]; [CL]

- Because every `$` call is itself an event, "intercept another mod's X" is uniformly available: hook `<namespace>.<method>` with a matcher; this is how `sec-default` and policy mods work.

## Key question 3: What UI surfaces can a mod draw, and can it draw on Claude Desktop?

### Takeaway
A mod draws via `ui.render` at 14 named render sites (own `Pane` and shared `AbovePrompt` band, plus Claude Code's own rows: `UserMessage`, `AssistantMessage`, `ToolUse/ToolResult/ToolGroup`, `CommandOutput`, `AskUserQuestion`, `ToolProgress`, `Spinner`, `TurnDuration`, `InfoNotice`, `SessionMode`, `PromptHint`) and can also raise toasts, a status line, log lines, native notifications and a question dialog; the permission prompt is explicitly not reachable. Desktop draws `Pane`, `AbovePrompt`, messages, tool rows, `AskUserQuestion`, `Spinner`, `CommandOutput`, `SessionMode`, `PromptHint`, with `Svg` but without `Raster`/`Image`.

### Cited Findings
- Render-site table (site / `e.props` / `e.requestId` / rendered on): `Pane` (`title`, `isFocused`, `bodyColumns`, `placement`, `scroll`, `view`; the pane's `id`; Terminal, Desktop, VS Code); `AbovePrompt` (`hasSurvey`, `isWorking`, `maxRows`, `bodyColumns`, `scroll`, `view`; one instance; Terminal, Desktop); `UserMessage` (`text`, `origin`, `isExpanded`, `task` or `from`; message id; T/D/VS); `AssistantMessage` (T/D/VS); `ToolUse`, `ToolResult`, `ToolGroup` (tool call id; T/D/VS); `CommandOutput` (`command`, `text`; T/D); `AskUserQuestion` (T/D/VS); `ToolProgress` (`kind`; Terminal); `Spinner` (`word`, `message`, `suffix`, `mode`; agent id; T/D/VS); `TurnDuration` (`word`, `durationMs`; Terminal); `InfoNotice` (`text`, `command`; Terminal); `SessionMode` (`modes`; T/D); `PromptHint` (`isDraft`, `isWorking`, `hint`; T/D). `e.viewport` holds `columns`, `rows`, `isFullscreen`. — [REF](https://code.claude.com/docs/en/plugins/mods/reference)
- Elements table (Terminal / Desktop / VS Code): `Box` ✓✓✓; `Text` ✓✓✓; `Button` ✓✓✓; `Link` ✓✓✓; `Code` ✓✓✓; `Markdown` ✓✓✓; `Input` ✓✓✓; `Select` ✓✓✓; `Svg` (≤131,072 chars) — Desktop, VS Code only; `Client` (`module`, `key`) — Terminal, Desktop; `Raster` (`columns` ≤512, `rows` ≤256, `cells`) — Terminal only; `Image` (PNG/RGBA ≤2 MiB or file path; ≤255×255; `alt`) — Terminal only. — [REF](https://code.claude.com/docs/en/plugins/mods/reference)

## Key question 4: What state/persistence does a mod get, and how does it interact with `userConfig`?

### Takeaway
Three tiers: module variables (lost on reload), `$.state` (reactive, per session, declared in `types/index.d.ts`, survives reload, reset by `/clear`/`/resume`/`/branch`), and `$.store` (JSON KV shared by every session on the machine, under `~/.claude/plugins/store/`, 4 MiB). `userConfig` values arrive as `register`'s `options`, are stored under `pluginConfigs` in settings, show as `/config` rows, and a change reloads the module.

### Cited Findings
- Keep-state table: module-level variable lasts until "The module reloads, which happens every time you save a file during development"; `$.state` lasts until "The session ends, or the user runs `/clear`, `/resume`, or `/branch`"; `$.store` lasts until "Your mod deletes it, or no session reads or writes the store for `cleanupPeriodDays`. The store is a key-value store, saved as a JSON file of your plugin's own under `~/.claude/plugins/store/`." — [IF](https://code.claude.com/docs/en/plugins/mods/interface)
- `$.state` declaration: `declare module 'claude-code' { interface PluginState { 'hello-tabs': { tab: 'one' | 'two'; count: number } } }` in `types/index.d.ts`, named by `"types": "./types/index.d.ts"` in `plugin.json`; helpers `import { atom, read, update } from 'claude-code'`; `const count = atom({ plugin: 'hello-tabs', key: 'count' }, 0)`; `await read($, count)`; `update($, count, v => v + 1)`. Rules: `plugin`/`key` as string literals; hold each `atom` in a `const` (a `let` fails with `takes a source the scan can read`); every value declared (else `hello-tabs.count is not declared`); "a `ui.render` hook can read state and can't write it". Reading in a render hook subscribes it, so writes redraw without `$.ui.invalidate`. `update` writes with `ifVersion` and retries on a miss. `derive(sources, fn)`, `memberOf(family, e)`, `StateFamily<T>` exist. "Only the owner writes a value; another plugin changes it by hooking `state.set`". — [IF]; [SKILLREF]
- After `/clear`/`/resume`/`/branch`, `$.state` resets and `session.start` does not fire; reload saved values in `on('classic.SessionStart', { source: ['clear', 'resume', 'fork'] }, ...)`. — [IF](https://code.claude.com/docs/en/plugins/mods/interface)
- `$.store` is shared across sessions and `get`+`set` is not atomic; advice: one key per item, re-read right before writing. `$.fs.write` "isn't atomic... Keep data that several sessions change in `$.store`." — [IF]; [REF]
- `userConfig`/options: "`options` holds the values of the fields the manifest's `userConfig` declares"; "Options for a plugin loaded this way are read from settings under `pluginConfigs`, keyed by the plugin's `<name>` (or `<name>@inline`); each non-secret `userConfig` field is a row in the config menu too, and a change there reloads the module with the new `options`. A `string` field that lists `options` (`"options": ["gist", "turbo"]`, its `default` among them) is a picker over exactly those values". — [SKILLREF]; [REF]
- Validation of options at load: `hooks module did not load: options do not fit plugin.json userConfig:` (e.g. number above `max`, required field unset); "The end of the line names its `pluginConfigs` entry in `settings.json`." — [TS](https://code.claude.com/docs/en/plugins/mods/troubleshoot)
- `claude plugin configure <plugin>` (2.1.285) "show[s] a plugin's options and which are unset"; 2.1.288 fixed `--plugin-dir` plugins not showing "Configure options" in `/plugin`. — [CL](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)
- `config.set`/`config.describe` events let a mod veto or relabel `/config` rows; `$.config.list`/`$.config.set` read/write them. 2.1.292 fixed `/theme` saving before a plugin's `config.set` hook was asked. — [REF]; [CL]
- Tests: `test(name, { options }, body)` gives the plugin its `userConfig` values "which it reads as the values stored in settings (a value outside a field's `options` unset, defaults filled in, then validated); left out, the plugin gets its manifest's defaults." — [SKILLREF]
- Session ids/persistence helpers: `$.session.id()`, `$.session.turns()`, `$.session.usage()`; `$.plugin.root()` gives the plugin directory. — [REF]

### Inferences
- `${CLAUDE_PLUGIN_DATA}` (the per-plugin data dir exported to settings hooks and MCP subprocesses, per this repo's CLAUDE.md) is not mentioned anywhere in the mods docs; a mod's documented persistence is `$.store` (plus arbitrary `$.fs` paths). A mod wanting to share state with bash hooks would have to use `$.fs` on a path both agree on, or `$.env.get` to read the variable if the host exports it to the hooks worker — not documented.

### Gaps
- Whether `$.env.get('CLAUDE_PLUGIN_DATA')`/`CLAUDE_PLUGIN_ROOT` are populated inside the hooks worker is undocumented.
- Secret (`sensitive`) `userConfig` fields: the skill reference says only "each non-secret `userConfig` field is a row in the config menu"; whether sensitive values reach `options` is not stated in the pages read.

## Key question 5: Can a mod register slash commands, tools, agents, or skills? Can it intercept tool calls, prompts, agent spawns, compaction, model switches?

### Takeaway
Yes to commands (`$.command.register` + `command.run`), tools (`$.tool.register` + `tool.call`, exposed as `mcp__<plugin>__<name>`), and agent types (`$.agent.register`, `<plugin>:<name>`); skills cannot be registered from a mod (they ship as files), but `skill.prompt` can rewrite any skill's expanded text. Tool calls, permission decisions, prompts, system-prompt sections, agent spawns (model choice/deny), compaction (`session.compact` → `{ skip }`), and per-request model/effort (`turn.step`) are all interceptable; a "model switch" event in the settings-hook sense is reachable only as `classic.PreModelSwitch`/`classic.PostModelSwitch` (inferred), not as a native mod event.

### Cited Findings
- Commands: register in `session.start` ("Claude Code waits for that hook before the first prompt"); `argumentHint` shows after the command; `immediate: true` lets it run while Claude is working; return `{ text }` (printed and read by Claude), `{}` (print nothing), `{ text, context }`; a `CommandOutput` render site lets the mod draw the output row as a tree. — [API](https://code.claude.com/docs/en/plugins/mods/api); [SKILLREF]
- Tools: `$.tool.register({ name, description, inputSchema })`; served by `on('tool.call', { tool: 'mcp__my-mod__ticket' }, ...)` returning `{ result }`; "a call no hook answers fails saying so"; re-registering replaces; `isDeferred: false` (2.1.293) loads it upfront against MCP tool search. `tool.describe` can also rewrite any tool's description and `isDeferred`. `agent.offer` `{ isOffered: false }` hides an agent type from the model. — [API]; [SKILLREF]; [REF]
- Agents: `$.agent.register` "declares an agent type the same way, `<plugin>:<name>`, from an agent definition as settings JSON spells one (prompt, tools, model, and the rest, all in force); a plugin folder's `agents/*.md` files declare them too. `$.agent.spawn({ subagentType })` runs one". 2.1.296 fixed `$.agent.register` succeeding from a stale hook after reload (now `$.agent.register refused: the hooks module that made the call is no longer loaded`). — [SKILLREF]; [TS]; [CL]
- Intercept tool calls: `tool.call` can deny before run, rewrite args via `next({...e, ...})`, retry, answer with `{ result }` (no permission prompt; "for a built-in tool, give `result` the shape that tool's own result has"), or withhold after `await next(e)`; hold with `$.ui.ask`. `tool.check` returns `allow`/`ask`/`deny` after rules and settings hooks, so "it can also approve a call that a `PreToolUse` hook outside managed settings blocked"; where `sec-default` loads, deny rules win unless `allowModsToOverrideDenyRules`. In auto mode, a hook-rewritten input causes `a hook changed this call's input after the model wrote it`. — [EV]; [ADMIN]; [TS]
- Intercept prompts: `prompt.submit` rewrite/add `context`/drop (2.1.295/2.1.299/2.1.300 fixed rewritten or dropped prompts still being recorded "as typed"); `prompt.section`/`prompt.compose`/`prompt.context`/`prompt.attachment`/`skill.prompt`; `prompt.mention` to redirect/deny `@file` reads; `prompt.autocomplete` adds rows; `prompt.fill`/`prompt.suggest`/`prompt.edit`/`prompt.change` observe the prompt box; `$.prompt.submit` starts a turn from a background job ("Claude reads the text after a sentence that names your mod as the sender" unless `asUser: true`). — [REF]; [EV]; [API]; [CL]
- Intercept agent spawns: `agent.spawn` → `next({ ...e, model })` or `{ deny }`; teammates (`e.isTeammate`, 2.1.289), workflow agents incl. rewriting `prompt`/`model` (2.1.292/2.1.300); not re-raised on `SendMessage` resume (match that tool in `tool.call` instead); 2.1.299 fixed it not running "when a finished subagent or a killed teammate is resumed". — [REF]; [CL]
- Compaction: `session.compact` fires "The conversation is about to be compacted"; returns `{ skip: reason }`; per the skill reference its result carries the compaction call's `ModelUsage`; `classic.PreCompact` is also hookable. `$.session.compact` triggers one. `claude plugin validate` on this repo prints: "hooks on session.compact, attribution.text do not run in a plugin a person installs where an organization manages Claude Code: there, these events pass over the plugins you install, and only a plugin the organization lists in managed settings runs them". — [REF]; [SKILLREF]; local `claude plugin validate` output (2.1.302)
- Model control: `turn.step` → `next({ ...e, model })` or `next({ ...e, effort })` sends one request to a different model/effort; `$.model.complete`/`fork`/`classify` make side calls on the session's credentials; `$.session.model()` reads the current model. — [REF]; [EV]
- Conversation rows: `session.append` can rewrite text blocks and `tool_result` content/`is_error` of every stored row (main and subagent conversations); `$.session.append` adds a user-role `isMeta` row or a `system` notice; policy/organization plugins see the event past user plugins. — [SKILLREF]
- Cross-session messaging: `$.session.send` to `{ sessionId }`/`{ agentId }`/reply address; `session.receive` `{ consumed }` keeps a message from Claude; `e.origin.kind` ∈ `peer`, `peer-send-message`, `task-notification`, `scheduled-trigger`. — [API]
- Other mods: `plugin.register` `{ refuse }` and `engine.create` (add/withhold a `$` noun). — [REF]

### Inferences
- Settings-hook events `PreModelSwitch`/`PostModelSwitch` (added in Claude Code 2.1.251 per this repo's CLAUDE.md) should be reachable as `classic.PreModelSwitch`/`classic.PostModelSwitch` because "Each settings hook event... is an event named `classic.<Event>`" — not explicitly confirmed in any page read.

## Key question 6: What are the validator's hard rules and the directory's policy rules on mods (MOD_* codes)?

### Takeaway
`claude plugin validate <dir>` statically reads the module and refuses anything it cannot follow: `$` must be written in full at each call site (passing `$` only to top-level function declarations in the same file, or to `read`/`update`), event names must be string literals, one unmatched registration per event, no shadowed `on`, no dynamic `import()`, relative imports only, ≤2,000 nested scopes, `$.state` keys declared in the `types` contract. The plugin directory layers reviewer-side `MOD_*` findings on top (hold vs block), known only from this repo's own submission record, not from a public policy page.

### Cited Findings
- Static-analysis rules (official): "Write each mods API call in full: `$`, the namespace, then the method... You can pass `$` to a function declared at the top level of the same file, and... the `calls:` line then reads `$.store.get (via loadNotes)`. Passing `$` to a method, a function defined inside the hook, or a function you import from another of your files fails validation. The `read` and `update` functions that `$.state` uses are the imports that can take it. Don't assign `$` or one of its namespaces to a variable, destructure it, or index it with a computed name. `const ui = $.ui` fails with `$.ui is used as a value`." Event names must be string literals (`the event name passed to on() is not a string literal`); no second `on` variable (`"on" is declared again (shadowed)`); relative imports only plus bare `claude-code`; no `import()` (`a dynamic import(); a hooks module imports its own files with an import declaration`); ES modules only. — [CREATE](https://code.claude.com/docs/en/plugins/mods/create)
- One registration per event per matcher: module fails to load with `on("session.start") is registered twice without a matcher`. — [EV](https://code.claude.com/docs/en/plugins/mods/events)

## Key question 9: How do the testing harness and typing work (`claude plugin test`, stubs, `claude-code.d.ts`)?

### Takeaway
`claude plugin test [dir]` runs `*.test.ts`/`*.test.tsx` files that import `test`, `expect`, `mock`, `describe`, `tier` from `claude-code/testing`; the test's `$` fires events through the mod, `on` registers stubs beneath it (returning `{ value }` for `$` calls or the event's own result), `mock.clock/store/env/session` supply the world, and `$.ui.mount` drives drawings per surface. Types come from `.claude-plugin/types/` which the engine writes on load from a folder you own (never in `-p` since 2.1.295).

### Cited Findings
- Test shape: `test('name', async ($, on) => { ... })`; `$` "acts as Claude Code. It isn't the mods API that a hook receives. Each of its methods fires the event of the same name"; `on` registers stubs "named for a mods API call without the `$.`" returning `{ value }` (`returned neither { value } nor { deny }` and `no implementation for <name>` are the common errors); event stubs return the event's own result (`tool.call` → `{ result }`, `session.start` → `{ cwd }`, `prompt.submit` → `{ text }`, `turn.complete` → `{ text }`, `session.send` → `{ isDelivered }`, `ui.render` → `{ type: 'Text', props: {}, children: [...] }`); `{ deny: reason }` makes a `$` call reject. Register every stub before the first `$` call. `session.start` doesn't run by itself. `turn.step` stubs are async generators. Kit-answered calls: `$.ui.invalidate`, `$.state`, `$.session.append`. `expect` has `toBe`, `toEqual`, `toMatch`, `toMatchObject`, `toContain`, `toBeDefined`, `toBeUndefined`, `toThrow`, `.not`. Exit status 1 on failure; prints `claude plugin test: hooks modules are turned off` if mods can't load. Every file needs a `test()` (`declares no test(): nothing ran`). — [TEST](https://code.claude.com/docs/en/plugins/mods/test)
- Mocks: `mock.clock(on, { now? })` → `advance(ms)`, `set(ms)`, `now()`, `settle()`, `sleep(ms)`; `mock.store(on, { ... })`; `mock.env(on, { ... })`; `mock.session(on)` → `appended()` (2.1.293+). — [TEST]
