# Multi-platform coding-agent plugin and skill ecosystem landscape (as of 2026-10-17)

Scope note: notes for a maintainer of a 29-skill / 10-agent / 29-hook / 1-mod plugin targeting Claude Code, Claude Desktop, Codex CLI, Cursor, Gemini CLI and OpenCode, deciding what to adopt for a v5 release. Sources are primary (vendor docs, spec repos, project READMEs) wherever one could be fetched; secondary blogs are marked as such. Every dated claim carries its source; where sources conflict, both are given.

## Which multi-platform plugins are best-in-class, and what concretely makes them so?

### Takeaway
obra/superpowers is the reference multi-harness plugin by a wide margin (300k+ stars, 16 harness install paths from one repo, a behavioral cross-CLI eval lab, deterministic per-harness packaging), but its own community criticism centers on token cost, bloat and until recently a lack of published evals. The next tier (anthropics/skills, vercel-labs/skills + skills.sh, supabase/agent-skills) wins by being *skills-first and format-portable* rather than by shipping hooks/agents to many hosts. Nobody fetched ships the full "skills + agents + hooks + mod" surface to six hosts with per-host CI like this repo does.

### Inferences
- "Best-in-class" in Oct 2026 = (a) skills written to the open spec so a single `skills/` tree is readable by 40+ agents without transformation, (b) a thin per-host manifest directory per harness rather than per-host copies of skills, (c) deterministic per-host packaging scripts (superpowers' `package-codex-plugin.sh`, supabase's Release Please tarballs), (d) a behavioral eval lab that drives the *real* CLIs rather than only Claude's `claude plugin eval`, and (e) an explicit token-cost story (superpowers 6.1/6.4.2 shipped bootstrap compression and leaner plans specifically in response to cost criticism).
- Superpowers' hook strategy — a single SessionStart bootstrap that tells the agent to read skills, degraded per harness (Pi re-injects after compaction; Antigravity has no SessionStart so it relies on skill discovery) — is the industry's de-facto portability pattern for hook-less hosts. This repo's 29 hooks are far beyond what any peer ships cross-platform; the measured Cursor-guard approach already in CLAUDE.md is more rigorous than anything found in the field.
- Community sentiment is converging on "skills à la carte, minimal always-on context, prove it with evals." A v5 that leads with per-component install, published Δ scores, and a measured always-on token figure would be differentiated.

## What does the Agent Skills spec require, and which fields are portable across all five platforms?

### Takeaway
The spec (agentskills.io, authored by Anthropic, reference impl `skills-ref`) requires only `name` and `description`; the full portable set is `name`, `description`, `license`, `compatibility`, `metadata` (string→string map), and experimental `allowed-tools`. Every Claude-only field this repo uses (`effort`, `user-invocable`, `disable-model-invocation`, `context`, `agent`, `model`) is outside the spec; OpenCode and Codex both read the portable five and put host extensions under `metadata`.

### Cited Findings
- Spec frontmatter: `name` (required; 1–64 chars; lowercase a–z, 0–9, hyphens; no leading/trailing/consecutive hyphens; **must match parent directory name**), `description` (required, 1–1024 chars, non-empty), `license` (optional), `compatibility` (optional, 1–500 chars, environment requirements), `metadata` (optional map string→string, "make key names reasonably unique"), `allowed-tools` (optional, space-separated, "Experimental. Support may vary") — [agentskills.io/specification](https://agentskills.io/specification)
- Directory conventions: `SKILL.md` required; optional `scripts/`, `references/`, `assets/`; progressive disclosure: metadata ~100 tokens loaded at startup, instructions "< 5000 tokens recommended", resources on demand; keep `SKILL.md` under 500 lines; file references one level deep; validate with `skills-ref validate ./my-skill` from `github.com/agentskills/agentskills/tree/main/skills-ref` — [agentskills.io/specification](https://agentskills.io/specification)
- Site pages include "Best practices", "Optimizing skill descriptions", "Evaluating skill output quality", "Using scripts in skills", and "How to add skills support to your agent" — [agentskills.io/llms.txt](https://agentskills.io/llms.txt)
- Client showcase lists 44 products including Claude Code, Claude, ChatGPT & Codex, Cursor, Gemini CLI, OpenCode, GitHub Copilot, VS Code, Amp, Kiro, Roo Code, Goose, OpenHands, Factory, pi, Junie, Letta, Hermes Agent, OpenClaw, Mux, Emdash, Snowflake Cortex Code, Databricks Genie Code, Spring AI, Mistral Vibe, Tabnine, Pulumi Neo, Laravel Boost, Qodo, TRAE, Workshop, ZeroClaw, nanobot, fast-agent, bub, Vita, Superconductor, Deep Code, Google AI Edge Gallery, Agentman, Command Code, VT Code, Firebender, Autohand, Piebald — [agentskills.io/clients](https://agentskills.io/clients.md)
- OpenCode reads `.opencode/skills/`, `.claude/skills/`, `.agents/skills/` (project; walks up to the git worktree) and `~/.config/opencode/skills/`, `~/.claude/skills/`, `~/.agents/skills/` (global); supports exactly `name`, `description`, `license`, `compatibility`, `metadata`; OpenCode-specific keys live in `metadata`: `opencode/slash` (expose as `/name`) and `opencode/autoinvoke: "false"` (hide from model auto-selection); permission rules `permission.skill` with `allow`/`deny`/`ask` and wildcards; per-agent `skill: false` — [opencode.ai/docs/skills](https://opencode.ai/docs/skills/)

- Gemini CLI: Agent Skills previewed Jan 2026 (v0.23.0), extensions can bundle skills (installed to `~/.gemini/extensions/<name>/skills`), enabled by default with a `skill-creator` skill by v0.26.0; precedence built-in < extension < user/workspace — [gemini-cli discussion #16084](https://github.com/google-gemini/gemini-cli/discussions/16084); [discussion #17812](https://github.com/google-gemini/gemini-cli/discussions/17812); [Google Cloud Medium](https://medium.com/google-cloud/your-gemini-cli-extensions-just-got-smarter-introducing-agent-skills-a8fbfa077e7f) (secondary)

- Claude Code's `claude plugin details` counts a component's always-on cost as `name` + `description` + `when_to_use` frontmatter; official marketplace shows a highlighted "Context cost" when always-on ≥ 2,000 tokens — [code.claude.com plugins/measure](https://code.claude.com/docs/en/plugins/measure)
- The Agent Plugins spec requires skills to be immediate children of `skills/` containing a regular `SKILL.md`, no deeper search, and to "follow the Agent Skills specification"; invalid skills are skipped and should be reported — [agent-plugins-spec 1.0.0](https://github.com/agentplugins/agent-plugins-spec/blob/main/spec/1.0.0.md)
- Snyk's ToxicSkills (2026-02-05) scanned 3,984 skills from ClawHub and skills.sh: 36.82% had ≥1 security issue, 13.4% critical, 76 confirmed malicious; 91% of malicious skills used prompt injection; 10.9% of ClawHub skills had hardcoded secrets; recommended `uvx mcp-scan@latest --skills` — [Snyk ToxicSkills](https://snyk.io/blog/toxicskills-malicious-ai-agent-skills-clawhub/)

### Inferences
- Portable across all five of this repo's platforms: `name`, `description`, `license`, `compatibility`, `metadata`. `allowed-tools` is portable in syntax but only enforced by Claude Code (OpenCode uses `permission.skill` instead; Codex has its own hook trust). A v5 lint rule that fails any SKILL.md whose non-portable keys sit outside `metadata` would align with how OpenCode (`opencode/*`) namespaces host keys, though Claude Code itself reads its extension fields at top level — so a dual-write (top-level for Claude, mirrored under `metadata` for others) is the realistic path.
- Directory-name = `name` is a hard spec constraint that `skills-ref validate` enforces; this repo's existing schema check should be verified against `skills-ref` as a second validator in CI.

## Which standards or conventions emerged in 2026 that a plugin should align to?

### Takeaway
Four things crystallized in 2026: (1) **Agent Plugins 1.0** (Aug 6, 2026; Vercel-proposed, built with AWS, Cursor, GitHub, Microsoft, OpenAI; adopted by Codex, Cursor, Copilot, VS Code, Kiro, ChatGPT — not Anthropic) as the root `plugin.json` + `skills/` + `mcp.json` package with reverse-domain `extensions`; (2) **AGENTS.md** under the Linux Foundation's Agentic AI Foundation, now read by Claude Code too (2.1.277, when no CLAUDE.md); (3) **MCP 2026-07-28** (stateless, sessions removed, Roots/Sampling/Logging deprecated, MRTR replaces server-initiated elicitation, extensions framework incl. MCP Apps and Tasks, CIMD over DCR); (4) **Claude Code mods** (2.1.287) as an in-process extension model. Hook formats remain per-host but Codex, Cursor and Copilot all alias `CLAUDE_PLUGIN_ROOT`/`CLAUDE_PLUGIN_DATA` and accept exit-code-2 blocking, so Claude's hook shape is the de-facto interchange format.

### Cited Findings

**Agent Plugins (agent-plugins.org)**
- Spec 1.0.0 "Status: Published"; `plugin.json` required fields: `$schema` (`https://agent-plugins.org/schemas/1.0.0/plugin.schema.json`) and `name` (1–64 chars; lowercase letters, digits, hyphens, periods; no `--` or `..`); optional `version`, `description`, `homepage`, `repository`, `author{name,email,url}`, `license` (SPDX), `keywords`, `extensions`; schema is closed — unknown top-level fields are reported and ignored, loading continues — [agent-plugins-spec 1.0.0](https://github.com/agentplugins/agent-plugins-spec/blob/main/spec/1.0.0.md)
- `mcp.json`: `$schema` + `mcpServers` only; transports `stdio` (`command`, `args`, `env`, `cwd`), `streamable-http` (`url`, `headers`), `sse` (deprecated); non-loopback hosts must be HTTPS; no secrets in `headers`; v1 defines no OAuth/credential fields (client-managed); `${PLUGIN_ROOT}` and `${PLUGIN_DATA}` must be set as env vars and expanded in `args`/`env`/`cwd` — [agent-plugins-spec 1.0.0](https://github.com/agentplugins/agent-plugins-spec/blob/main/spec/1.0.0.md)
- Extensions: client-specific manifest data under `extensions.<reverse-domain>`; client-specific files in a top-level directory named after the namespace (e.g. `com.example.client/hooks/`); clients ignore unknown namespaces — [agent-plugins-spec 1.0.0](https://github.com/agentplugins/agent-plugins-spec/blob/main/spec/1.0.0.md)
- Client conformance minimum: validate manifest, discover components in fixed locations, ignore unsupported types, support ≥1 of stdio/streamable-http if MCP is supported, isolate failures per component — [agent-plugins-spec 1.0.0](https://github.com/agentplugins/agent-plugins-spec/blob/main/spec/1.0.0.md)
- 1.1.0 is a "Working Draft" that still defines exactly two component types (skills, MCP servers); "commands, hooks, agents, rules, and LSP servers" remain outside v1 — [agent-plugins-spec 1.1.0](https://github.com/agentplugins/agent-plugins-spec/blob/main/spec/1.1.0.md)
- Published 2026-08-06; proposed by Vercel, built with AWS, Anysphere (Cursor), GitHub, Microsoft, OpenAI; launch clients ChatGPT, Codex, Cursor, GitHub Copilot, Kiro, VS Code; Anthropic absent; Claude Code keeps its own format — [blakecrosley.com](https://blakecrosley.com/blog/agent-plugins-standard) and [composio.dev](https://composio.dev/content/what-are-agent-plugins) (secondary); transport naming trap: standard says `streamable-http`, Claude's `.mcp.json` says `http`, neither valid in the other — [codex.danielvaughan.com](https://codex.danielvaughan.com/2026/08/08/agent-plugins-1-0-open-standard-codex-cli-portable-skills-mcp-packaging/) (secondary)
- Example/migration repo exists — [agentplugins/agent-plugins-example](https://github.com/agentplugins/agent-plugins-example)

**Codex (OpenAI) packaging**
- Portable layout: root `plugin.json` with `$schema` agent-plugins 1.0.0 and OpenAI settings under `extensions.com.openai` (`apps`, `hooks` [path | array | inline], `onboardingSkill`, `interface{displayName, shortDescription, longDescription, developerName, category, capabilities, websiteURL, privacyPolicyURL, termsOfServiceURL, defaultPrompt, brandColor, composerIcon, logo, screenshots}`); `.codex-plugin/plugin.json` remains a compatibility fallback used only when `extensions.com.openai` is absent — the two are not merged; `mcp.json` auth under `extensions["com.openai"].auth` with `type` none/oauth/mixed/api_key and OAuth `mode` provided/dcr/cimd — [developers.openai.com/plugins/build/plugins](https://developers.openai.com/plugins/build/plugins)
- `marketplace.json` at `$REPO_ROOT/.agents/plugins/marketplace.json`, `~/.agents/plugins/marketplace.json`, or legacy `.claude-plugin/marketplace.json`; entries need `name`, `source`, `policy` (`installation`: AVAILABLE | INSTALLED_BY_DEFAULT | NOT_AVAILABLE; `authentication`: e.g. ON_INSTALL), `category`; sources `local`, `url`, `git-subdir` (`ref`/`sha`), `npm` — [developers.openai.com/plugins/build/plugins](https://developers.openai.com/plugins/build/plugins)
- **Lifecycle hooks are supported only for manually installed Codex desktop plugins; "Plugins with hooks aren't eligible for the public directory."** Default discovery `hooks/hooks.json`; explicit `hooks` replaces it; commands get `PLUGIN_ROOT`/`PLUGIN_DATA` and `CLAUDE_PLUGIN_ROOT`/`CLAUDE_PLUGIN_DATA`; installing a plugin "doesn't automatically trust its hooks" — [developers.openai.com/plugins/build/plugins](https://developers.openai.com/plugins/build/plugins)
- Codex hook events (12): `SessionStart`, `SessionEnd`, `PreToolUse`, `PostToolUse`, `PermissionRequest`, `UserPromptSubmit`, `Stop`, `Interrupt`, `PreCompact`, `PostCompact`, `SubagentStart`, `SubagentStop`; handler types `command` and `mcp_tool` run, `prompt`/`agent` are parsed but skipped; trust is tied to the hook's hash (changed hooks are skipped until re-trusted; `/hooks` to review; `--dangerously-bypass-hook-trust`); exit 2 blocks; `hookSpecificOutput.permissionDecision`, `updatedInput`, `additionalContext` supported; `ask`, `updatedMCPToolOutput`, `updatedPermissions` cause hook failure; `suppressOutput` parsed but unimplemented — [learn.chatgpt.com/docs/hooks](https://learn.chatgpt.com/docs/hooks)
- Codex plugins launched 2026-03-26/27 (secondary); `codex plugin list --json` in v0.137; v0.147.0 (2026-08-07) added portable Agent Plugins installs — [codex.danielvaughan.com](https://codex.danielvaughan.com/2026/04/24/codex-cli-plugin-marketplace-building-distributing-extending/) (secondary)

## What testing and release practices do the best plugins use?

### Takeaway
The 2026 baseline is: schema validation in CI (`claude plugin validate`, `skills-ref validate`), a behavioral eval suite with a no-plugin baseline (`claude plugin eval`, GA since 2.1.269 on 2026-09-11, six graders, Δ-reported, JSON+HTML, CI exit codes), cost measurement (`claude plugin details` always-on tokens), and for cross-host plugins a separate harness that drives the real CLIs (Quorum) but keeps live evals out of public CI. Release automation is tag-driven (Release Please, deterministic per-host packaging), and directory distribution is webhook-driven with automated security scans and a usage dashboard.

## What orchestration and agent-to-agent patterns are current? (coverage area 5)

### Takeaway
Claude Code now has three sanctioned layers — subagents, cross-session messaging (sockets, v2.1.224+), and experimental agent teams (shared task list with dependencies + file-locked claiming + JSON mailboxes + `TeammateIdle`/`TaskCreated`/`TaskCompleted` hooks) — plus channels (MCP servers pushing events in). Worktree-per-agent is the universal isolation pattern (built into Claude Code, Mux, Emdash, superpowers). Handoff protocols remain file-based and vendor-specific.

### Cited Findings
- Agent teams: enable `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`; lead + teammates (separate Claude Code instances, own context) + shared task list (pending/in progress/completed; dependencies unblock automatically; file locking on claims) + mailbox (`~/.claude/teams/{team}/inboxes/{agent}.json`, validated on read); team config `~/.claude/teams/{team}/config.json` removed at session end, tasks under `~/.claude/tasks/{team}/` persist; display modes in-process / tmux / iTerm2 `it2`; teammates can be spawned from subagent definitions (`tools`, `model`, `disallowedTools`, `effort`, `autoCompactWindow` [v2.1.296+], body; `skills` not applied); model precedence prompt → definition `model` → `CLAUDE_CODE_SUBAGENT_MODEL` → lead (before 2.1.251 env var came first; `_FORCE` from 2.1.257); plan-mode teammates get auto-approved plans; permission prompts bubble to lead; teammates don't inherit `dontAsk`; in auto mode the classifier treats relayed approvals as untrusted; hooks `TeammateIdle`, `TaskCreated`, `TaskCompleted` (exit 2 to block); limits: no resume of in-process teammates, task status can lag, one team per session, no nested teams, no background subagents from teammates, lead fixed; teammates use 5-min cache TTL unless `subagentPromptCacheTtl: 1h`; recommended 3–5 teammates, 5–6 tasks each — [code.claude.com agent-teams](https://code.claude.com/docs/en/agent-teams)
- Cross-session messaging: v2.1.224+ (Windows 2.1.234+); `ListAgents`/`SendMessage`; `@name` mentions (2.1.232+); same-machine via Unix socket `/tmp/cc-socks-<uid>` or named pipe, never Anthropic servers; cross-machine/cloud via Remote Control; `notify_when_idle` (2.1.236+, 12-h expiry); inbound controls `crossSessionInbound` accept/hold/refuse with default class rules (bypass vs prompting), `dialogExpiry` 5 min, 100 held max, 50 queued, loop throttling, ~1M-char cap; receiving Claude is told the message is from another session, it can't approve prompts or change config; hooks/Bash get `CLAUDE_CODE_MESSAGING_SOCKET` + `CLAUDE_CODE_MESSAGING_TOKEN` so a script can post into its own session; `isolatePeerMachines`; deny `SendMessage`/`ListAgents` to disable — [code.claude.com cross-session-messaging](https://code.claude.com/docs/en/cross-session-messaging)
- Channels (research preview): an MCP server pushes events into a running session (`claude --channels plugin:telegram@claude-plugins-official`); Telegram/Discord/iMessage/fakechat plugins in `claude-plugins-official/external_plugins`, require Bun; sender allowlists with pairing codes; optional permission-relay capability (allowlisted senders can approve tool use remotely); enterprise `channelsEnabled` + `allowedChannelPlugins`; "Being in `.mcp.json` isn't enough"; webhook-receiver pattern for CI/error-tracker events — [code.claude.com channels](https://code.claude.com/docs/en/channels)
- superpowers SDD: file-based handoffs, one reviewer per task, whole-branch review, per-plan workspaces, scratch in `.superpowers/sdd/` (moved out of `.git/` because Claude Code blocks writes there), worktree removal no longer force-deletes uncommitted files — [RELEASE-NOTES.md](https://raw.githubusercontent.com/obra/superpowers/main/RELEASE-NOTES.md)
- Worktree-per-agent products in the Agent Skills client list: Mux ("parallel coding agents, each with its own isolated workspace"), Emdash ("each isolated in its own git worktree, locally or over SSH") — [agentskills.io/clients](https://agentskills.io/clients.md)
- Secondary: external orchestrators (Conductor, Parallel Code) add dashboards and cross-repo worktree tracking; worktrees keep uncommitted changes isolated and the lead merges manually — [tembo.io](https://www.tembo.io/blog/claude-code-multi-agent-orchestration); [developersdigest](https://www.developersdigest.tech/blog/git-worktrees-claude-code-parallel-agents-guide)
- Codex hooks have `SubagentStart`/`SubagentStop`; Cursor has `subagentStart`/`subagentStop` (`ask` treated as deny) — [learn.chatgpt.com/docs/hooks](https://learn.chatgpt.com/docs/hooks); [cursor.com/docs/agent/hooks](https://cursor.com/docs/agent/hooks)

### Inferences
- This repo's `orchestrate-dev`/`worker-dev` fan-out and `.agent-worktrees/<objective>/` layout map cleanly onto agent teams (task list + dependencies + `TaskCompleted` gate) — a v5 could add `TaskCreated`/`TaskCompleted`/`TeammateIdle` hooks that enforce the handoff vocabulary and DoD, while keeping the subagent path as the portable fallback.
- The messaging socket + token means a *hook* (e.g. `rate-limit-handoff.sh`) can now post a structured message back into its own session or a sibling — a portable-on-Claude route for the `switch-dev` problem that mods solve in-process.
