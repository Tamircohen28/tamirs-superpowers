# Install on Antigravity CLI

**Platform:** Gemini. **Surface:** Antigravity CLI (`agy`) — registry id `antigravity_cli`,
**unverified**. This guide exists because Google retired Gemini CLI for consumer tiers on
2026-06-18 in favour of Antigravity CLI, and because Antigravity's plugin format is not a
Gemini extension. Nothing on this page has been measured against a live `agy` binary: none
was available where this was written, and the CLI is not open source, so there is no bundle
to read the way the [Gemini CLI guide](gemini.md) reads Gemini's. Every claim below is from
Google's documentation, and the places where the documentation stops are marked.

| | |
|---|---|
| **Validated against** | nothing — no live `agy` run yet |
| **Plugin folder** | [`platforms/antigravity/`](../../../platforms/antigravity/README.md) — `plugin.json` + `mcp_config.json`, generated by `scripts/build-antigravity-plugin.sh` |
| **Skills tree** | `.agents/skills/` (generated by `scripts/build-agents-skills.sh`) — the path Antigravity reads workspace skills from |
| **Adapter metadata** | [`platforms/antigravity/adapter.yaml`](../../../platforms/antigravity/adapter.yaml) |
| **Official docs** | [Plugins](https://antigravity.google/docs/plugins/) · [Migrating from Gemini CLI](https://antigravity.google/docs/cli/gcli-migration) · [MCP](https://antigravity.google/docs/mcp) |

## Who should be here, and who should not

Gemini CLI stopped serving Google AI Pro/Ultra subscribers and free individual Code Assist
users on 2026-06-18. If that is you, Antigravity CLI is the successor and this page applies.
If you use Gemini CLI through an **enterprise Code Assist Standard/Enterprise licence** or a
**paid Gemini API / Agent Platform key**, Gemini CLI still works and keeps receiving the
full adapter (hooks, policies, keychain-backed token) — use the [Gemini CLI guide](gemini.md).

## Route A — import the Gemini extension (documented)

Antigravity ships one command that converts installed Gemini extensions into native plugins:

```bash
# 1. Install the Gemini extension first (Gemini CLI guide, Method A), then:
agy plugin import gemini
```

Google's migration guide says the importer "searches your legacy local directories, parses your
extension manifests, and converts files into native layout blocks". What carries over, per that
guide:

| Gemini CLI | Antigravity | Status |
|---|---|---|
| `GEMINI.md` / `AGENTS.md` | unchanged — "No modifications are needed" | documented |
| workspace skills `.gemini/skills/` | `.agents/skills/` | documented; this repo ships `.agents/skills/` already, see below |
| global skills `~/.gemini/skills/` | `~/.gemini/antigravity-cli/skills/` | documented |
| `commands/*.toml` | converted to skills | documented; this repo ships no commands |
| MCP servers | `mcp_config.json` — `url`/`httpUrl` become `serverUrl`; stdio keeps `command`/`args` | documented |
| sub-agents | reported "skipped (none detected)" in Google's sample output | unverified for this repo's `.gemini/agents/` |
| `hooks/hooks.json` | not in the migration guide; the [hooks page](https://antigravity.google/docs/hooks) documents plugin `hooks.json` in the CLI | **unverified** — firing not measured |
| `policies/*.toml` | not mentioned | **unverified** |

## Route B — the native plugin folder (generated, unverified)

`platforms/antigravity/` is the native shape: a `plugin.json` that is exactly
`{name, description}`, and an `mcp_config.json` with the `github` stdio server. Two fields
only, because an earlier reading of the docs gave the schema as closed
(`additionalProperties: false`). The current [plugins page](https://antigravity.google/docs/plugins/)
example also shows `$schema`, `displayName`, `version`, `logo` and `suggestedPrompts`, so the
schema may no longer be closed; that is unverified until `agy plugin validate --strict` runs on
it, and the generator adds nothing until then. A plugin install is one of:

```bash
agy plugin install </path/to/plugin-folder>          # local path
agy plugin install https://github.com/<owner>/<repo>  # repo URL
agy plugin list --json
```

Workspace plugins live in `.agents/plugins/`, global ones in `~/.gemini/config/plugins/`, and
CLI installs are staged under `~/.gemini/antigravity-cli/plugins/<name>/`.

What is **not** known, and why this route is not recommended yet:

- **MCP server path.** Antigravity documents stdio servers as `{command, args, env, cwd}` with
  absolute example paths and defines no placeholder for the plugin directory (nothing like
  Gemini's `${extensionPath}`). The generated `mcp_config.json` uses a path relative to the
  plugin root; whether `agy` resolves it against the plugin directory is unverified. Route A
  yields absolute paths because the Gemini extension is already installed somewhere concrete.
- **Hooks.** The folder ships **no `hooks.json`**, deliberately. Antigravity's
  [hooks page](https://antigravity.google/docs/hooks) now documents plugin `hooks.json` in the
  CLI and the `PreToolUse` decision values, and Google says hooks carry over from Gemini
  extensions "at launch" without 1:1 parity; one third-party source says `agy` loads hooks but
  does not fire them, and no firing has been measured here. A hooks file that loads and never fires reads as a guard
  that is not one. The worktree, sensitive-file and branch guards are therefore **not active on
  Antigravity** until a live run shows a hook fire; until then they are what the skills tell the
  agent to do by hand ([`core/policies/safety.md`](../../../core/policies/safety.md)).
- **Token.** Antigravity's plugins page now documents required **config variables**: a plugin
  that declares them installs disabled, and enabling it opens a setup dialog for each one. The
  generated folder declares none, and the mechanism has not been exercised here.
  `scripts/github-mcp.sh` reads `GITHUB_PERSONAL_ACCESS_TOKEN` from its environment, so export it
  in the shell that starts `agy` or put it in the server's `env` block yourself. Nothing in the
  generated file carries a token.

## Skills: one tree, no install step

`.agents/skills/` at the repo root is a generated flat mirror — one relative symlink per skill,
`.agents/skills/<name> -> ../../skills/<domain>/<name>` — because every host that reads
`.agents/skills/` (Antigravity, Gemini CLI as the `.gemini/skills` alias, Codex, Copilot) scans
exactly one level deep and this repo's canonical tree is two. With the repo as your workspace,
Antigravity should find every skill in place; from a release tarball the links are already
dereferenced into plain directories. Regenerate after adding a skill:

```bash
bash scripts/build-agents-skills.sh .          # regenerate
bash scripts/build-agents-skills.sh . --check  # fail on drift (runs in CI)
```

## Verify

```bash
agy plugin list --json          # the plugin, with its component lists
```

and, in a Gemini CLI that is still available to you, the same extension with
`gemini extensions list` — the two should agree on the context file, the MCP server and the
skills.

## Update

Route A: update the Gemini extension, then re-run the import:

```bash
gemini extensions update tamirs-superpowers
agy plugin import gemini
```

Route B: `agy plugin install` the new folder again (the documented commands have no in-place
update; a reinstall replaces the staged copy under `~/.gemini/antigravity-cli/plugins/`).
Both are documented commands, neither has been run here.

## Uninstall

```bash
agy plugin uninstall tamirs-superpowers
```

Skills imported into `.agents/skills/` or `~/.gemini/antigravity-cli/skills/` are plain
directories after an import; remove the ones you no longer want by hand. A clone's own
`.agents/skills/` is part of the repo and needs nothing.

## Moving a row off "unverified"

Every capability row for `antigravity_cli` in [`core/capabilities/platforms.json`](../../../core/capabilities/platforms.json)
is `unknown`. The only thing that changes that is a live run recorded there: `agy --version`,
`agy plugin install` of the generated folder, `agy plugin list --json` showing the skills, and —
for the hooks row specifically — a `BeforeTool`-equivalent hook observed firing. If you have an
Antigravity licence and run any of these, the output is the contribution.

Validation of what this repo can check without the binary:

```bash
bash scripts/build-antigravity-plugin.sh . --check   # generated files match their sources
bash tests/test-antigravity-adapter.sh               # two-field plugin.json, MCP shape, no hooks.json, adapter contract
bash tests/test-agents-skills.sh                     # the .agents/skills mirror
```
